What is on this sheet

A column under the status bar: the header row (36dp settings button, 12dp, "Your Library" in 26/31 bold, then a 26dp search glyph and a 28dp plus glyph in 48dp targets; padding start 16, end 8, top 8), the chip row (16dp side padding, 10dp above and below, 8dp between chips), the sort row (18dp sort glyph, 8dp, label in 14/18 semibold, a 48dp icon button at the right; padding start 16, end 8), then the list or grid. List rows are the Search result row with a 64dp cover. Grid tiles are three across with 14dp between columns and 16dp between rows.

Spotify cues on this screen

  • "Your Library" as the tab label and the screen title, with the books icon (ui/LibraryScreen.kt:134, ui/AppRoot.kt:112-116).
  • The header arrangement: avatar-style round button, bold title, search and plus icons at the right, a row of pill chips beneath, then a sort label with a grid toggle (ui/LibraryScreen.kt:126-202).
  • "Recents" with a sort glyph (:192-194).
  • One list mixing playlists, artists (round) and albums, each with its type as a subtitle prefix: "Playlist, 31 songs", "Artist", "Album, Shashwat Sachdev" (:99-114).
  • "Liked Songs" and its violet-to-mint tile with a white heart (ui/HomeScreen.kt:381-389).
  • "Downloaded" as a filter (ui/LibraryScreen.kt:55), and the green down-arrow badge on every song row under it.
  • The selected chip in the accent green with black text.
  • "Give your playlist a name" as the dialog title (:225).
  • The tab bar and the mini player, as on every sheet.

Things that look odd and are correct

  • "Recents" looks like the sort control it is modelled on and is a plain label. The order is fixed.
  • The search icon in the header does not search this screen. It switches to the Search tab.
  • The header's two icon buttons end 8dp from the screen edge and the grid toggle sits in the same column, so the toggle's 20dp glyph is centred under the 28dp plus.
  • The filter named "Downloaded" shows every song in the library, and is the only way to reach a flat song list.
  • Singles are "Album, {artist}" in the library and "Single" on their own screen.
  • Artists are split from credit lines, so one soundtrack contributes many artist rows with the same cover (frame G, and library.png).
  • With no filter the list is long: seven playlists, up to 40 artists, then every album. Albums start several screens down.
  • In the grid, a row is as tall as its tallest tile, so a two-line title pushes the next row down for all three columns.
  • A round artist tile centres its name and "Artist" as boxes. A name that wraps becomes a full-width box, so its two lines are left-aligned above a centred "Artist" (frames B and I; ui/LibraryScreen.kt:250-253).

Guessed

  • Frame D has no keyboard. The field requests focus when the dialog opens, so on a phone the keyboard is up and the dialog sits higher. The keyboard is the system's and is not drawn. Dialog width and dim are the kit's platform defaults.
  • The order of the two user playlists. The code lists them in the order the database returns them.
  • "Recents" order beyond the four songs sheet 01 shows under "Recently played": everything not played recently falls back to name order, as in the code.
  • Folder order is by name (English, Hindi, Phonk, Tamil), as data/LibraryBuilder.kt:65 sorts them.
  • Covers for artists the brief does not list are the cover of an album they appear on.
  • The first twelve song titles under "Downloaded" are the fixture's songs in title order. The other 76 songs of the 127 are not named in the fixture and would be interleaved.

Not drawn here

The playlist screen the dialog leads to is on sheet 04. The track menu and the other two titles of the name dialog ("New playlist", "Rename playlist") are on sheet 07. Your Library with no songs has no layout of its own: the list holds Liked Songs at "Playlist, 0 songs" and any user playlists.
