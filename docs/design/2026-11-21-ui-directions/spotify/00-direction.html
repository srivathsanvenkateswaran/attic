Direction: the current tokens

2026-11-21 · UI directions · spotify · sheet 00

This folder is the baseline: the UI exactly as it ships today, redrawn in HTML from the Kotlin in app/src/main/java/app/attic/player/ui/. It proposes nothing. This sheet documents the tokens the current app runs on and shows every reusable component from kit.css on its own.

The list at the bottom is every cue that makes the app read as Spotify, grouped by where it lives. It is the checklist the three proposals are measured against.

How the tint is drawn in these mocks

Real artwork is not used. shared/covers.css gives each fixture cover a mid-tone --tint, and kit.css applies the app's rule to it as hsl(from var(--tint) h min(s, 62) clamp(20, l, 30)). Blends that the code composites (black 72% or 55% over the tint, white 10% over it, the tint at 40% over white) use color-mix() with the same percentages.

What makes it read as Spotify

From CURRENT-UI.md section 5, unchanged. These are the cues a redesign has to remove or replace.

Stated intent

  • README.md:8 calls it "A Spotify-style player".
  • ui/Theme.kt:87 comments "Spotify has no light mode to copy, so this mirrors the dark roles."
  • ui/HomeScreen.kt:442 describes the settings button as sitting "in the spot where a streaming app shows your profile".

Guesses on this sheet

  • The progress-bar track colour. Theme.kt does not set secondaryContainer, which the current Material 3 linear indicator uses for its track, so the track is drawn in Material's baseline #4A4458 (dark) and #E8DEF8 (light). No screenshot shows a progress bar.
  • Dialog width (328dp) and the 60% dim behind dialogs are Android and Material defaults read from the platform theme, not values in the app's code.
  • Playing bars and the spinner are drawn at one moment of their animation.
