Library

2026-11-21 · UI directions · One UI · sheet 03

Library is drawn the way One UI draws a file list: a bare large title, a row of actions that closes the viewing area, filter chips, then labelled cards. Today's unfiltered list already runs playlists, then artists, then albums. Each run becomes its own card under its own label, which takes the type word off every second line.

The sheet settles where each control lives. What acts on the app sits in the tools row: search, create playlist, settings. What acts on the list sits at the right end of the label above it: the view toggle, and the sort for the all-songs list. "Shuffle all songs" is the first row of the song card.

What was kept

  • Four filters, none selected at first, each cleared by a second tap.
  • What each filter holds and its order: Favourites, user playlists, folders; artists and albums by how recently one of their songs was played, then by name.
  • List and three-column grid, one toggle. No toggle in "Songs".
  • "Search your library" switches to the Search tab and does not filter this screen.
  • "Create playlist" on every filter. Confirming creates the playlist and opens it.
  • Sorting by "Title", "Artist" or "Recently added". "Shuffle all songs" plays everything from a random song, context "All songs". Tapping a song plays the whole list from that row.
  • Folders and user playlists are both playlists here and look the same.

Open questions

  • Type words dropped. "Playlist, 31 songs" becomes "31 songs", "Album, A. R. Rahman" becomes "A. R. Rahman" and "Artist" goes, because the card's label says it. These are current strings outside the naming table, so the owner should agree to losing them. Search keeps them, where types share one shelf.
  • "Recently played first". This replaces the word "Recents" and is a new string. It is true of artists and albums only, which is why it is not above the whole list.
  • The index. It is not in the app today. It is a way to move through a list, and it needs nothing new stored, but it is an addition. It shows only for the title order and only once the title has collapsed, since the list is too short for 27 letters before that.
  • Sort as a menu. The orders are the same and are all visible before choosing, at the cost of a second tap to reach "Artist". Cycling on tap, as today, needs no pop-over.
  • The toggle scrolls away. It belongs to the first label, so after scrolling it is out of reach until the list is back at its top, as in a One UI file list. A fourth icon in the bar would keep it reachable and crowd the bar.
  • Settings as a gear. One UI would put settings behind a "more options" menu. The gear stays direct to match Home, which makes the tools row search, plus, gear.
