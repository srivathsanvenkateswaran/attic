Attic · UI directions

Design round · 2026-11-21 · branch ui-redesign · mocks only, nothing in the app has changed
Right now, the UI is a rip off of Spotify. While it is good to use, I don't think we can publish it without inviting copyright strikes or something. […] It should follow Google's Material standards and it should look like as if we build an offline music player for Google Pixel Devices, with Pixel UI Experience. […] Also propose another style of UI, like the OneUI style of UI and Apple Music Style of UI.

The current app was first extracted screen by screen into CURRENT-UI.md, then drawn four times: once as it ships today, and as three proposals. Every folder has the same eleven sheets with the same frames and the same library, so any screen can be compared across all four.

Each proposal borrows a platform's design language and gives Attic its own accent, an open-licence typeface and its own icons. None of them is meant to pass for Samsung's, Apple's or Google's own music app; swapping one copied product for another would not solve the problem.

What each proposal asks you to decide

Questions the designers left open. Each sheet's closing notes carry the detail.

Pixel

  • Home's shortcut carousel shows Favourites and about one and a half covers at a time. Today's grid shows all six. The fallback is two rows of three.
  • The heart moved from beside the song title to the tools row under the transport.
  • Now Playing follows the light theme. Today it is always dark.
  • Artists are a nine-lobed cookie everywhere. A rounder square is the quiet alternative.
  • A phone without dynamic colour needs one fixed fallback scheme. None is chosen yet.

One UI

  • "127 songs on this phone" under the Home title is the one string that is not on Home today.
  • Instant mixes are paged rows of three, so seeing all nine takes two swipes.
  • The heart sits in the control deck, one row lower than today.
  • The amber accent is close to the Recap palette's marigold and to Plex's brand colour. It is two tokens per theme to change.
  • The typeface has no Indic scripts; Tamil or Devanagari titles would fall back to Noto Sans.
  • The floating dock follows One UI 8.5 and would look a release ahead on One UI 7.

Apple Music

  • The ember accent sits between orange and red. One token changes it.
  • Now Playing follows the light theme with a pale field. Today it is always dark.
  • Settings is a gear on the title row, so the mark no longer sits where a profile picture would.
  • Instant mixes are rows in columns: three visible, six a swipe away.
  • Home still has four shelves of covers under bold headings, which is on the Spotify cue list.
  • Glass needs backdrop blur, which Android only does well from Android 12 and not in widgets.

After you pick

  1. Say which direction, which rows of the naming table to overrule, and your answers to that direction's open questions. Mixing is fine: a screen from one direction can be redrawn in another's language.
  2. Pick a logo, or name the two you want pushed further.
  3. The chosen direction gets one correction round on its mocks, then becomes the spec: tokens into Theme.kt, then screen by screen in Compose, starting with the shell, Home and Now Playing.
  4. The uncommitted song-radio and Wrapped work is sitting on this branch. It should be committed before the Compose work starts, so the restyle has something stable to change.
