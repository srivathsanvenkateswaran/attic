Settings and system states

2026-11-21 · UI directions · apple · sheet 08

Settings is the one screen in this direction built from boxes: grouped inset lists on the page colour, a sentence-case label above each and small print below. It keeps every control and every status sentence the current screen has. What moves is where each sentence sits: the fact goes in the card, the action is a row of Ember text under it, and the privacy note is the footnote.

The states around the app (no permission, first scan, empty folder, a missing album) carry no artwork, so they are type on Soot or Paper with Ember only on the button. Each one says what to do next.

Kept

  • Sections "Appearance", "Lyrics", "Song radio", "About" in that order, with "Match phone", "Dark", "Light" and "Dark" as the default.
  • Every sentence from section 2.15, word for word: the saved-lyrics count, the lrclib.net note, "Checked … of …, found …", both failure messages, "Autoplay" and its description, the on-device note, the three analysis statuses, and the About line with its song count.
  • "Download lyrics for all songs" hides while a run is in progress. "Analyse now without a charger" shows only when analysis is idle and songs remain. The analysis bar is always visible.
  • The mini player and tab bar stay on Settings and on the missing-item screen. The permission and loading screens have neither.
  • Permission title and both bodies and buttons. Empty-library and missing-item titles and bodies.

Where this differs from Apple Music

  • Apple puts an app's settings in the system Settings app. Attic's are a screen inside the app, reached from the gear on each tab, with the mini player still under it.
  • The check, the switch and the action rows are Ember, not system blue or Apple Music's red.
  • The permission page uses the title-page layout iOS uses for onboarding, but the button leads to Android's permission prompts and, once refused, to Android's app-permissions page. There is no "Not now".

Open questions

  • Theme as a list or a segmented control. Three rows with a check match the language picker and leave room for "Match phone" at any font size. The kit's segmented control would do it in one 40dp line and save 110dp.
  • "Song radio" and "Autoplay". Section 5 lists both names among the Spotify cues; the naming table keeps every settings label. They are drawn as they are today.
  • New copy. "Reading Music/Offline" on the loading screen and the "Back" button on a missing item. Both can go.
  • Permission layout. KIT.md suggests the centred empty-state block for this screen. This sheet sets it left-aligned with the button at the bottom, to tell first run apart from an empty list. If you prefer the centred form it is the kit's .empty.mid with the same strings.
  • Glass over nothing. On the empty Home the tab bar floats over a blank page, which the direction otherwise avoids. It is the only screen where that happens.
